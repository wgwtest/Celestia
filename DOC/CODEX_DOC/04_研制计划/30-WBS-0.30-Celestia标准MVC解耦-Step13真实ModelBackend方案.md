# Celestia MVC Step13 Real Model Backend Implementation Notes

## 1. 目标

Step13 的目标是让独立 `celestia-model-host` 能在 headless 模式下加载真实 Celestia 数据目录，并持有真实 `Universe / Simulation / Observer` 状态。

本步骤不解决真实 `scene.frame` 投影，也不声明跨进程 View3D 已达到历史 in-process renderer 的视觉保真。

## 2. 已完成能力

已完成：

- `RuntimeConfig` 支持 `--data-root=`，并能把该路径传入 runtime assembly resources。
- `RuntimeAssemblyRunner` 可以从 `contentRoot` 或 `contentRoot/run-full` 解析真实 Celestia data root。
- `RuntimeSession` 只给 Model host 传递 `--data-root=`，Controller / View host 不接收该参数。
- `celestia-model-host` 在收到 `--data-root=` 时创建真实 Model backend；未配置时保持原 synthetic backend。
- `RealModelBackend` 可以加载 `celestia.cfg`、`stars.dat`、DSO、SSO，并创建真实 `Universe`、`Simulation`、`ObserverSettings`。
- `ModelService` 可以使用注入的 backend 输出真实 `ViewFrame` snapshot。
- 独立 `celestia-model-host` 可在 `stdio-pipe` 三进程 runtime 中完成 ready/start/tick/shutdown 闭环。

测试可靠性同步修复：

- `test/CMakeLists.txt` 增加 `${target}_runtime_dependencies`，确保 Windows 测试目录内的 `celestia.dll` 随 `celestia` shared target 更新；否则 `unit.exe` 可能优先加载旧 DLL，导致验证结果失真。

## 3. 初始化分类

本轮按 `rg -n "initSimulation|Universe|StarDatabase|Observer|Simulation|CelestiaCore|AppWindow|SDL|OpenGL" src/celestia src/celengine src/celruntime` 梳理后，分类如下。

### Pure Model Initialization

当前 Step13 只复用以下无 SDL window 依赖的模型初始化链：

- `ReadCelestiaConfig`
- `loadStars`
- `loadDSO`
- `loadSSO`
- `Universe`
- `Simulation`
- `ObserverSettings`
- `SceneViewModel::buildSelectionSnapshot`

### Application Shell Initialization

仍属于历史应用壳层，不在 Step13 迁移范围内：

- `CelestiaCore::initSimulation`
- console / HUD row setup
- favorites / destinations / local user config merge
- Lua hook / script startup
- application-level fatal error handling

### View And Window Initialization

仍属于 View 或 historical frontend：

- SDL `AppWindow`
- SDL event loop
- OpenGL context creation
- historical `Renderer`
- `celestia-view3d-host` render loop

### Resource Path Initialization

Step13 仍使用历史 loader 所需的 path handle：

- `engine::TexturePaths`
- `engine::GeometryPaths`
- `celestia.cfg` relative path resolution
- `data/`, `extras/`, `textures/`, `models/` 等 content-root 下资源路径

注意：`TexturePaths` / `GeometryPaths` 当前头文件仍位于历史 `view3d` 路径下。这是 loader 复用带来的过渡性依赖；Step13 没有把 SDL window、OpenGL context 或 renderer 对象引入 Model 协议。

### Script And UI Initialization

以下能力未进入 Step13：

- demo scripts
- CELX / Lua runtime hook
- menu / HUD / overlay text management
- UI destinations and favorites presentation
- Qt / Win32 frontend-specific startup

## 4. 实现要点

### Runtime Data Root

`RuntimeConfig` 新增：

- `dataRoot()`
- `setDataRoot()`
- `applyRuntimeConfigArgument("--data-root=...")`

`RuntimeAssemblyConfig::fromRuntimeConfig(...)` 在未显式传入 `contentRoot` 时使用 `runtimeConfig.dataRoot()`。

`RuntimeAssemblyRunner` 对 assembly `contentRoot` 做解析：

- 如果 `contentRoot/celestia.cfg` 和 `contentRoot/data` 存在，直接作为 Model data root。
- 否则尝试 `contentRoot/run-full`。
- 否则不传递 `--data-root`，继续走 synthetic backend。

### Model Host Backend Selection

`celestia-model-host` 的入口规则：

- 带 `--data-root=`：创建 `createRealModelBackend()`。
- 不带 `--data-root=`：保持原 synthetic backend。

`RuntimeSession` 只在 `host.role == RuntimeRole::Model` 时追加 `--data-root=`，并在 session log 记录：

```text
model dataRoot=<path>
```

### Headless Logger

真实 loader 链会调用 `celestia::util::GetLogger()`。历史统一 exe 会在应用入口初始化 logger，但独立 model host 不经过该入口。

Step13 在 `RealModelBackend::load()` 开始处补齐 headless logger 初始化：

```text
if GetLogger() == nullptr:
    CreateLogger(Level::Warning)
```

该修复避免独立 `celestia-model-host` 在 `loadStars(...)` 中因空 logger 访问而崩溃。

## 5. 可以说

可以说：

- 独立 Model host 现在可以加载真实 Celestia data root。
- 独立 Model host 可以创建真实 `Universe / Simulation / ObserverSettings` 状态。
- Model host 可以从真实 simulation snapshot 输出至少一个真实 body 或 star selection。
- 三进程 runtime 可以把解析到的 `run-full` data root 传给 Model host，并完成 Debug2D runtime 闭环。
- Step13 没有把 SDL window、OpenGL context 或 renderer 类型放入 Model 输出协议。

## 6. 不能说

不能说：

- `scene.frame` 已经完整投影真实 Celestia 场景。
- 跨进程 View3D 已经具备历史 in-process renderer 的视觉保真。
- Model 层整体已经完全冻结。
- 全部 Celestia 资源已经进入最终 ResourceRef / data-plane 规范。
- Qt / Win32 能力已经由本步骤验证。

## 7. 对 Model Lock 的影响

Step13 仍处在“核心语义锁执行中”的阶段：

- 没有为 View 改写 `Universe / Body / Star / Orbit / Timeline` 核心语义。
- 允许修改 Model backend facade、Runtime data-root 装配和只读 snapshot 输出。
- Model 层完全冻结仍需等待 Step17 后确认。

## 8. 当前限制

当前限制：

- `SceneExtractor` 仍主要把 `ViewFrame` selection 转成现有 `scene.frame` 字段，真实 body/star/orbit/resource 投影还未完成。
- `RealModelBackend::snapshot()` 当前优先选择 `Sol/Earth`、`Earth` 或第一颗 star 作为代表性 selection；不是完整场景枚举。
- `TexturePaths` / `GeometryPaths` 仍来自历史 loader 体系，后续 Step17 需要进一步稳定资源引用。
- `RuntimeAssemblyRunner` 对 data root 的解析是本地构建布局导向，尚不是最终发布安装布局规范。
