# Celestia MVC Step15 Real View3D Scene Consumption Implementation Notes

日期：2026-06-27

## 1. 目标

Step15 的目标是让跨进程 `celestia-view3d-host` 消费 Step14 产生的真实 `scene.frame` 字段，而不是只证明协议消息可以送达。

本 Step 完成后，可以说：

```text
View3D host 已能读取真实 scene.frame 的 body、star、orbit、label、resource 字段。
View3D host 已能通过 content root 解析 ResourceRef.relativePath。
runtime assembly 可把真实 Model scene.frame 送入独立 View3D 进程。
SDL 统一 exe 的 multi-process 入口可传递真实数据目录给 Model 和 View3D。
```

仍不能说：

```text
跨进程 View3D 已达到历史 in-process Celestia Renderer 的视觉保真。
View3D 已完整复刻历史纹理、网格、光照、遮挡、星等、标签和 UI 渲染策略。
Resource/DataPlane 已完成最终高性能资源通道。
```

## 2. 范围

本 Step 修改范围：

```text
src/celruntime/view3d/view3dscene.*

src/celruntime/view3d/view3dhost.*

```

本 Step 不修改历史 renderer 核心，不把 `Universe`、`Simulation`、`Observer` 或 OpenGL 内部句柄暴露给协议消费者。

## 3. 实现内容

### 3.1 View3D scene state

新增 `View3DSceneState`：

```text
sequence
simulationTime
cameraFov
bodyCount
starCount
deepSkyObjectCount
orbitCount
labelCount
resourceCount
resolvedResourceCount
missingRequiredResourceCount
resources
```

`buildView3DSceneState()` 只消费 `protocol::SceneFrame` 和 content root，不访问 Model 内部对象。

### 3.2 ResourceRef 解析

新增 `resolveSceneResources()`：

```text
ResourceRef.relativePath -> contentRoot / relativePath
exists -> filesystem existence
resolvedPath -> normalized filesystem path
```

该解析遵守 Step12 `ResourceRef.relativePath` 规则：View3D 只能解析协议输出的相对资源路径，不能接收进程本地 pointer、OpenGL handle 或绝对路径作为协议语义。

### 3.3 View3D host 报告真实消费结果

`View3DHost` 增加 `View3DHostOptions.contentRoot`，收到 `scene.frame` 后构建 `View3DSceneState`。

`view.ready3d` payload 更新为：

```text
renderer=step15-scene-consumer;capabilities=scene.frame,view.input,opengl,resources;frames=0
```

`view.frameRendered` payload 增加：

```text
frameCount
lastSequence
simulationTime
bodyCount
starCount
deepSkyObjectCount
orbitCount
labelCount
resourceCount
resolvedResourceCount
missingRequiredResourceCount
cameraFov
```

这些字段用于机测证明 View3D 不是只收到了消息，而是消费了真实场景字段。

### 3.4 Runtime content root 传递

`RuntimeSessionOptions` 和 `View3DHostLoop` 增加 content root 传递。

当 view 为 `celestia.view3d.opengl` 时：

```text
Model host 接收 --data-root=<real data root>
View3D host 接收 --content-root=<real data root>
```

`ProcessSupervisorOptions` 增加 `contentRoot`，避免 `--serve` 路径把 runtime host 目录误当成 Celestia 数据目录。

### 3.5 SDL 统一 exe multi-process 数据目录解析

`sdlmain.cpp` 增加数据目录解析：

```text
--dir build-mvc-sdl-rel
```

如果该目录下存在 `run-full`，则实际 content root 解析为：

```text
D:\WorkSpace\Codex\CeleNew\Celestia\build-mvc-sdl-rel\run-full
```

并把绝对路径传给 Model 和 View3D，避免 host 进程在不同 cwd 下把相对路径解释错。

## 4. 历史 Renderer 参考边界

本 Step 复用的历史概念：

```text
相机 FOV
天体、恒星、轨道、标签、资源引用
Celestia 数据目录作为内容根
```

本 Step 禁止迁入 View3D 协议消费层的历史依赖：

```text
Universe*
Simulation*
Observer*
Renderer*
Texture*
Mesh*
GLuint / OpenGL 内部 handle
SDL window / GL context 句柄
历史 CelestiaCore 指针
```

保留的视觉差距：

```text
纹理贴图未按历史 Renderer 完整绑定。
mesh、星等、颜色、标签布局、光照和遮挡仍是简化实现。
真实资源解析已完成，但 Resource/DataPlane 还不是最终高性能通道。
```

因此 Step15 的结论是“真实 scene.frame 消费成立”，不是“历史 Renderer 视觉保真成立”。

## 8. 对 Step16 的入口条件

Step16 可以在 Step15 合并或继续在同一集成分支上开始。入口条件：

```text
Step15 focused tests 保持通过。
View3D view.frameRendered payload 能证明真实 scene.frame 字段已被消费。
SDL --serve 路径能把真实 content root 传给 Model 和 View3D。
不把 Controller 输入直接绑定到 View 本地指针或窗口资源。
```

Step16 的主要任务是形成：

```text
View input -> Controller command -> Model state -> scene.frame -> View
```

闭环，而不是继续扩大 View3D 视觉保真范围。
