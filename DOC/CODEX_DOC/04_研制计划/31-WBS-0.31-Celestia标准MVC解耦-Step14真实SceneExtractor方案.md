# Celestia MVC Step14 Real SceneExtractor Implementation Notes

## 1. Goal

Step14 moves `scene.frame` generation from Step8 placeholder output to a first real projection layer backed by real Celestia `Simulation / Universe / Observer / Selection` state.

This step does not claim full historical View3D visual parity. It provides real time, observer/camera, selected body/star, orbit sample, label, and resource references in the existing `scene.frame vNext` protocol shape.

## 2. Implemented Scope

Implemented:

- `ViewFrame` now carries read-only projection DTOs for time state, camera, observer, resources, bodies, stars, and orbits.
- `viewframecodec` serializes and deserializes these fields so independent Model host payloads preserve the real projection data.
- Legacy `ipc::RuntimeMessage` ViewFrame serialization embeds the full `viewframecodec` payload so it no longer drops Step14 fields.
- `SceneViewModel::buildSelectionSnapshot(...)` reads real `Simulation`, active `Observer`, selected `Body` or `Star`, and sampled body orbit points.
- `RealModelBackend::snapshot()` adds real catalog `ResourceRef` inputs from `celestia.cfg`, including `data/stars.dat` and `data/solarsys.ssc`.
- `SceneExtractor` prefers real projected fields when present and keeps the Step8 synthetic fallback for legacy/synthetic frames.
- Step14 tests prove real `scene.frame` output is placeholder-free for the real backend path.

Not changed:

- No Celestia celestial core semantics were rewritten for View.
- No `Simulation*`, `Universe*`, `CelestiaCore*`, renderer object, texture handle, mesh handle, or GPU id is exposed through `scene.frame`.
- `sceneprotocol.*` did not need new fields; Step12 fields were sufficient for this first real projection layer.

## 5. Current Capability

It is correct to say:

- The real Model backend can now produce a `ViewFrame` snapshot with real observer/camera, selected body/star, sampled orbit, and catalog resources.
- `SceneExtractor` can project that snapshot into a valid `scene.frame vNext`.
- The real backend `scene.frame` no longer uses Step8 placeholder meshes, placeholder textures, synthetic bodies, or `stars/sol-placeholder.stc`.
- The multi-process view-frame payload path preserves the new real projection fields.
- Model core semantics remain owned by existing Celestia model/controller code.

It is not correct to say:

- Cross-process View3D is now visually equivalent to the historical in-process renderer.
- The entire `Universe`, full star database, all DSO objects, all textures, and all mesh references are projected.
- Resource/data-plane behavior is final.
- Controller interactions have complete historical behavior parity.
- Model layer is fully frozen. That still waits for later Step17/Step18 confirmation.

## 6. Model Lock Impact

Step14 completes the first practical "core semantics unchanged, output protocol projection changed" layer:

- `Universe`, `Body`, `Star`, `Orbit`, `Timeline`, and observer algorithms are not rewritten for View.
- The changed surfaces are limited to read-only snapshot DTOs, serialization, projection, backend resource references, and tests.
- The model facade still evolves through Step15-Step17 because View3D consumption, controller feedback, and resource/data-plane hardening may expose required protocol refinements.

The stronger "Model layer fully frozen" claim is still not valid.
