# Celestia 标准 MVC 解耦 Step21 SolarSystem 类族 MVC 拆解计划

> 本文是 Step21 的执行计划。目标是处理 Step20 后唯一仍造成 `src/celengine/model` 直接 include `src/celengine/adapter` 的 catalog 类族问题。本文不把 SolarSystem 误判为 Model 架构层剩下的唯一问题；Star / DSO 类族仍有 builder、texture、render-assets 债务，但它们当前不形成 `model->adapter` 硬 include。

## 1. 目标

Step21 的直接目标:

```text
消除 src/celengine/model/universe.h -> celengine/adapter/solarsys.h 的直接依赖。
```

完成后应达到:

1. `SolarSystem` / `SolarSystemCatalog` 作为 Model 对象图实体进入 `src/celengine/model`。
2. `SolarSystemsBuilder` 继续留在 adapter/loading 侧，不随本轮迁入 Model。
3. `solarsys.cpp` 中涉及 `.ssc` 解析、`GeometryPaths`、`TexturePaths`、`BodyRenderAssets`、mesh/texture manager 的逻辑不被错误搬入 Model。
4. `tools/mvc/scan_mvc_boundary_debt.ps1` 中 `model->adapter` 分类清零。
5. `model->view` 和 `model-view-symbol` 保持 0。
6. 统一 exe、runtime smoke、截图回归不退化。

## 2. 非目标

本轮不做:

1. 不重写 `.ssc` 解析器。
2. 不迁移整个 `src/celengine/adapter/solarsys.cpp`。
3. 不把 `SolarSystemsBuilder` 强行归入纯 Model。
4. 不处理 Star / DSO 的 builder/render-assets 债务。
5. 不重构 `ViewFrame`、`SceneFrame` 或 runtime 输出协议结构。
6. 不开始原 View3D 模板 View 搬迁。

## 3. 当前源码事实

当前硬依赖:

```text
src/celengine/model/universe.h
  -> #include <celengine/adapter/solarsys.h>
```

原因:

```text
Universe 持有 std::unique_ptr<SolarSystemCatalog>。
Universe 返回 SolarSystemCatalog* / SolarSystem*。
SolarSystem 和 SolarSystemCatalog 当前定义在 adapter/solarsys.h。
```

`solarsys.h` 当前混合:

| 实体 | 当前位置 | 职责判断 |
| --- | --- | --- |
| `SolarSystem` | `src/celengine/adapter/solarsys.h` | Model 对象图 |
| `SolarSystemCatalog` | `src/celengine/adapter/solarsys.h` | Model catalog 容器 |
| `SolarSystemsBuilder` | `src/celengine/adapter/solarsys.h/.cpp` | 加载构建，混入资源路径和 render assets |

`solarsys.cpp` 当前还直接触碰:

```text
BodyRenderAssets
GeometryPaths
TexturePaths
view3d/meshmanager.h
view3d/texmanager.h
```

因此本轮只能抽出 `SolarSystem` / `SolarSystemCatalog`，不能整体移动 `solarsys.*`。

## 4. 与 Star / DSO 类族的对照

| 类族 | 核心 catalog 是否在 model | Builder 是否仍在 adapter | RenderAssets 是否仍在 adapter/view | 是否形成 model->adapter 硬 include |
| --- | --- | --- | --- | --- |
| Star | 是，`stardb.*` | 是，`stardbbuilder.*` | 是，`starrenderassets.*` | 否 |
| DSO | 是，`dsodb.*` | 是，`dsodbbuilder.*` | 是，`nebularenderassets.*` | 否 |
| SolarSystem | 否，仍在 `adapter/solarsys.h` | 是，`SolarSystemsBuilder` | 是，`BodyRenderAssets` 等 | 是 |

本轮把 SolarSystem 作为特殊切片，是因为它是当前唯一造成 `model->adapter` 硬 include 的 catalog 类族，不是因为 Star / DSO 已经完全解耦。

## 5. 执行步骤

### Step21A. 固化验收测试

新增测试:

```text
test/scripts/test_mvc_model_adapter_boundary_clean.ps1
```

测试行为:

1. 调用 `tools/mvc/scan_mvc_boundary_debt.ps1`。
2. 如果输出包含 `[model->adapter]`，测试失败。
3. 如果 `model->view` 或 `model-view-symbol` 重新出现，也测试失败。

红灯预期:

```text
当前应因 Universe -> adapter/solarsys.h 失败。
```

绿灯预期:

```text
SolarSystem / SolarSystemCatalog 抽出后通过。
```

### Step21B. 拆出 Model 头和实现

新增:

```text
src/celengine/model/solarsystem.h
src/celengine/model/solarsystem.cpp
```

迁入:

```text
class SolarSystem
using SolarSystemCatalog
SolarSystem::SolarSystem
SolarSystem::~SolarSystem
SolarSystem::getStar
SolarSystem::getPlanets
SolarSystem::getFrameTree
```

不得迁入:

```text
SolarSystemsBuilder
.ssc parsing
GeometryPaths / TexturePaths
BodyRenderAssets
mesh / texture manager include
```

### Step21C. 调整 include 和 CMake

修改:

```text
src/celengine/model/universe.h
  include <celengine/model/solarsystem.h>

src/celengine/adapter/solarsys.h
  include <celengine/model/solarsystem.h>
  只保留 SolarSystemsBuilder 声明

src/celengine/adapter/solarsys.cpp
  删除 SolarSystem 方法定义

src/celengine/CMakeLists.txt
  model/solarsystem.* 加入 CELESTIA_MODEL_SOURCES
```

必要时更新直接消费者 include:

```text
只读取 SolarSystem / SolarSystemCatalog 的 UI / View 文件，应优先 include model/solarsystem.h。
仍使用 SolarSystemsBuilder 的加载文件继续 include adapter/solarsys.h。
```

## 6. 完成标准

Step21 只能在以下条件同时满足时视为本轮完成:

```text
model->adapter: 0
model->view: 0
model-view-symbol: 0
celestia-sdl / unit 构建通过
SelfTest 或 Quick 通过
Quick 截图矩阵完成
机测记录和交接文档更新
```

不能得出的结论:

```text
Model 层已经完全解耦。
Star / DSO 的 builder/render-assets 债务已经解决。
Runtime Model 输出已经完成分层。
View3D 已经可以直接模板化迁移。
```
